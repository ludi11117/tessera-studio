# 从偏好分歧到决策价值

2026-10-28。原product-v10工程增加决策论层，不改变16px界面、生成供应商、训练权重或任务数据。所有产物在D盘，本轮付费API调用0次。

## 对技术深度的判断

已有工程具备任务内语义偏好网络、明确标签、验证划分、检查点、可撤回反馈、有限组合约束求解和事务审计。这已经超过普通聊天界面，但此前的在线选题主要是网络分歧加回答熵，未直接度量询问是否改变最终推荐。真实用户收益、泛化和不确定性校准的证据仍弱。增加网络层数不能直接补齐这些问题。

本轮把技术链路延伸为：训练成员 → 可行方案上的效用假设 → 推荐风险 → 两种回答的条件推演 → 询问价值 → 明确用户反馈。相关决策论方向参照 [BoTorch的偏好采集函数文档](https://botorch.readthedocs.io/en/stable/acquisition.html) 与 [Preference Exploration原论文](https://arxiv.org/abs/2203.11382)。本实现是有限固定假设的一步条件枚举，不是BoTorch的GP/qEUBO复现。

## 实现与数学定义

`research/decision_value.py` 接受H×N效用矩阵：每行是一个模型假设，每列是一个满足所有硬条件的组合。线上使用三个实际训练的初始化成员，等权；同版本语义线性只有一个成员。

设效用为u_h(x)、假设权重为w_h。每个假设自己的最优效用为m_h=max_x u_h(x)。推荐a的预期后悔值：

`R(a) = Σ_h w_h [m_h − u_h(a)]`

均值推荐最小化R。另算最小最大后悔值方案 `argmin_a max_h [m_h − u_h(a)]`，用于预览对成员分歧更保守的搭配。它不替换原推荐，也不保证现实更好。

比较(i,j)时，在固定假设内以 `sigmoid(u_h(i) − u_h(j))` 建立二元回答似然。分别枚举回答A/B、计算回答概率P(y)、条件权重w_h|y，并在**全部可行组合**上重新选择最优推荐。询问价值为：

`V(i,j) = min_a R(a) − Σ_y P(y) min_a R(a | y)`

在有限假设与上述响应模型内，这个值可精确算出且非负；测试以独立全期望公式和双假设闭式数值验证。每个成员的整体分数平移不影响结果。没有梯度近似或新增模型请求。

两个重要反例：成员可能对无关方案分歧很大、回答熵很高，却一直推荐同一个第三方案，此时V为0；只有一个成员时V也为0，不能解释为已经知道用户偏好。

## 线上边界与可操作功能

- 从均值领先者、各成员首选和高分歧组合中组成最多24项询问候选池；只在池内未比较的组合对中选题。每种回答的最终推荐推演仍检查全部可行组合。查询池是近似筛选，不宣称找到全部方案对中的全局最佳。
- 正向收益超过数值阈值才按V排序；全部为零时明确记录回答熵回退，不虚构正向收益。沿用原预算、用户主动点击、随机展示顺序和跳过规则。
- 比较弹窗可展开“为什么比较这两份”，查看候选数、组合对数和推演值。规划元数据冻结模型指纹、分数表指纹、分支权重和推荐组合；模拟回答永远不写训练标签。
- 交付总览展示均值推荐的预期/最不利成员后悔值，以及最小最大后悔值方案。点击只预览，采用仍通过原版本和约束检查；结果随现有决策JSON进入交付包。
- 线上集成只是三个初始化网络，**不是校准的贝叶斯后验**。成员可能共同出错；后悔值是内部效用差，不是实际钱、工时、错误概率或正确率。
- 条件推演假设固定假设重加权；真实用户作答后仍沿用原有显式重新训练流程。推演结果不能冒充下一次神经网络重训的预测，也没有暗中持久化一套额外信念状态。

## 同预算离线对照

固定设计：两种真值设定，各12个种子；每例9个效用假设、12份可行方案；随机、回答熵、决策价值三策略；相同初始矩阵、可行集合、6次比较预算和响应随机数序列。真值只交给模拟回答与外部评分，不传入选题器。每策略连续更新条件权重，保存0/2/4/6次的真实模拟损失和推荐命中。

6次比较后的平均模拟后悔值，越低越好：

| 真值设定 | 随机 | 回答熵 | 决策价值 |
|---|---:|---:|---:|
| 真值位于假设集中 | 0.4223 | 0.6930 | 0.0642 |
| 真值来自假设集以外 | 1.0682 | 0.8148 | 0.4200 |

对应首选命中率分别为66.7%/66.7%/83.3%，以及25.0%/25.0%/33.3%。这些是小规模设计性模拟，不是用户研究，没有统计充分性或普遍优越性结论；尤其第二组仍有明显选错损失。实验使用9个固定假设重加权，不是在每个回合重训线上3个网络，不能直接外推线上收益。

可回放目录 `experiments/runs/decision-value-1793156018299393400` 保存输入、真值、噪声、完整查询轨迹、结果和算法/实验源码快照。`scripts/assess_decision_value.py` 每次写新目录，不覆盖旧实验；不调用API。
