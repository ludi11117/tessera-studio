2026-10-27，Asia/Shanghai。在现有工程上扩展，不另建产品。保留16px圆角与本地字体。代码在原D盘工程；所有新增验收库、下载与临时文件位于D盘。

## 实际可用的闭环

1. 进入任务的“目标与素材”。程序从明确字数区间、学习天数、素材中的未确认措辞提出验收建议。用户可编辑再“确认验收条件”。建议不是完整需求理解；被提取的来源短语也不一定都适合进入正文，必须核对。
2. 确认后，锁定、原长度限制与机器验收条件共同决定可行集合。“不同思路”显示遍历数量、合格数量和按条件排除的数量。逐个穷举已有三候选的组合，再按本任务偏好效用排序，分数相同时尽量少改原稿。数量最多仍是原来的3^6，不是开放世界规划器。
3. 只有明确compare且未撤回的选择参与学习。确认条件、查看检查、生成、修正、采用、锁定和编辑不产生标签。偏好不能覆盖硬条件；历史标签仍指向原来的不可变文字。比较快照与新导出的研究标签保留当时的验收条件。旧研究实验与数据不重写。
4. 点击“检查并修正未通过部分”才调用API。任务冻结版本、材料、范围、明确比较及可用的内容偏好预测。一次最多3次请求：独立审阅 → 必要修正 → 独立复验；没有可修正目标则只审阅，不凑调用次数。
5. 机器失败与模型定位的失败决定修改范围，锁定部分继续排除。修正不得新增章节。长度失败时计算保护文字占用、待修改章节的剩余字数预算；较大的扩写可要求分句后连接原样输出，不用程序填充或截断文字。
6. 每轮规则结果、文稿/条件/来源哈希、模型意见、改动与调用记录保存到草案；刷新可读取。模型修改先预览，再由用户采用。机器条件不通过或模型仍报告违例，不能采用。未知事项保持可见，最终仍由人工判断。正文、条件或素材改变后，旧复验显示为历史记录。
7. 不合格的现有正文可继续手动编辑为中间稿；整份组合采用、最终采用与导出检查已确认的机器条件。无解明确显示，不偷偷放宽条件。不会在刷新、启动或本地测试中调用模型。

## 机器条件的含义

| 条件 | 实现 | 不代表什么 |
|---|---|---|
| 总字数区间 | 正文去空白、素材引用编号后的Unicode字符数；不含章节标题和固定条件章节 | 不等同于汉字数、字节数或语义完整性 |
| 逐日覆盖 | 独立识别“第1天”等标记；“第1–7天”范围不能替代每天标记 | 不验证每天是否30分钟、依赖顺序是否正确 |
| 必须/禁止短语 | 对正文逐字出现进行检查 | 不理解同义改写、否定与上下文；可按任务调整 |
| 来源数字原文 | 可选，数字措辞需在目标、固定条件或当前材料中有相同原文；跳过代码围栏、URL和Markdown序号 | 不验证数字归属、推理、单位换算、资料真实性；可能排除合理的新建议与技术标识（如UTF-8中的8） |
| 需要判断的要求 | 发给独立审阅请求，保持用户复核 | 不能转换成可靠的确定性语义验收 |

来源数字选项仅在分析类且出现“只根据/仅根据/只使用/仅使用”时作为建议开启，确认前不是硬限制。没有检查项会显示“未设置检查项”，不能当成内容通过。

独立审阅是同一上游模型的另一次请求，使用单独的审阅系统提示，不是独立供应商、外部事实验证或人工评委。原文摘录和来源ID会校验；即使这些校验通过，判断本身仍会误检、漏检。未知事项也不等同于文稿错误。
