# 从对话到可操作的定制画布

2026-10-28，Asia/Shanghai。在原 product-v10 工程增量实现，未更换语言、数据目录、训练权重或界面体系。保留 16px 圆角、本地字体、石墨黑与柔白。入口：工作室 → 方案与定制 → 定制画布。

## 本轮实际改变

主视图是**章节 × A/B/C版本**矩阵。点选即保留，再点取消。每个格子显示在其余保留项、篇幅区间和改动上限不变时，选择该版本还能组成多少个满足当前机器条件的搭配。已锁定章节不可更换；零搭配仍可点选，以查看冲突。

辅助地图是**正文字符数 × 改动章节数**。同坐标合并为一个点并标数量，列表保留全部搭配，键盘可选择。地图不把篇幅短解释为质量高。实心点包含当前固定得分与改动量的非支配方案；图中显示所有筛选后的可行点。

选择后直接展示相对当前稿件的逐章原文差异。点击“完整预览与检查”进入已有定制器，并重新执行服务端检查；再点击“采用”才写入正文。保留项沿用原有“采用并固定”语义。切换稿件版本后重建画布，旧筛选不冒充当前结论。

相比只使用对话，这个交互减少的是具体操作负担：无需反复描述“保留哪几章”，无需在多份回答间人工数候选、找混搭，无解时能直接看有候选佐证的调整方向。筛选不发送生成请求，查看不产生偏好标签。**没有做与普通 Codex/聊天的真实用户对照，不能宣称节省了多少时间或模型质量更高。**

## 算法与可核对含义

服务端先使用原求解器与决策分析器核对相同可行集合，然后输出紧凑表：组合ID、章节版本ID、当前得分、正文字符数、相对当前稿件的改动数。表不重复正文，带独立内容指纹；绑定原 revision / task / state / materials / model 快照，并随“决策与约束证据.json”进入 ZIP。

浏览器 `static/configuration.js` 是纯计算模块，`static/canvas.js` 只处理交互与呈现；无第三方依赖。候选上限仍为 3^6=729，不放大搜索范围。

设原硬条件可行集合为 F，临时篇幅与改动范围过滤得到 W。对章节 i 的版本 v，建立位集 M(i,v)。用户保留项集合为 A：

`F_A = W ∩ ⋂_(i,v)∈A M(i,v)`

格子 (j,t) 的补齐数为：

`support(j,t) = |W ∩ M(j,t) ∩ ⋂_(i,v)∈A, i≠j M(i,v)|`

即替换这一行的保留要求，其他行继续保留。不能把同一行不同版本的数量相加解释为独立用户概率。

有解时最大化当前固定偏好分，平分优先少改动，再按ID稳定打破平局。没有明确反馈时，界面说明这是基线排序，不能解释为个人偏好收益。筛选不会更新模型，得分也不是质量、事实正确率或预测工时。

无解分成三类：原硬条件已经无解；W为空；保留项交集为空。只有第三类计算本次保留项的解释：

1. 删除式搜索得到一个不可再删冲突核，不保证条件数最少。
2. 对每个 W 内候选计算不满足的保留项集合，去掉严格包含其他集合的集合，得到全部包含关系最小的调整集合；返回前六组，每组附有可行候选见证。
3. 用户明确点击调整建议，才取消列出的临时保留项。原正文锁定、原长度上限、已确认机器条件始终保持。

这是有限配置搜索的工程实现，未引入新的神经网络训练算法。技术深度体现在与已有偏好网络、硬条件、可复核反事实和版本验收联动，不能将位集查询包装成新的大模型训练成果。

## 架构评估与实测

| 选择 | 预期收益 | 本轮判断 |
|---|---|---|
| 保留 Python HTTP / SQLite / NumPy / ONNX | 保持现有算法、训练、事务和启动入口，无数据迁移 | 采用；本轮未发现由语言造成的性能瓶颈证据 |
| 浏览器独立纯计算模块与UI模块 | 筛选无需往返服务端，可独立做穷举对照 | 已实现；没有新增框架或依赖 |
| 前端逐模块引入 TypeScript | 有助接口、空状态与异步状态检查 | 可后续渐进采用；会增加构建与类型维护成本，不能自行提升生成质量 |
| 整体迁移 Node/Rust/Go 服务层 | 只有明确部署、吞吐或运行时诉求时才可评估收益 | 当前缺少需求与基准支持；需重验事务、作业、凭证和ONNX边界，暂不做 |
