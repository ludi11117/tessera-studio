# Tessera · 拾构

**模型写候选，程序管提交、约束与交付。**

一个本地优先的 AI 创作工作室，面向不想研究提示词的人：从模糊目标出发，看具体方向、留下满意的局部，再把需求逐项落实到成果。

如果你只想看它与普通对话式生成的区别，打开 **`/proof`**：那里用隔离沙盒实时展示真实的 409 并发拒绝、事件快照链、有限约束求解、冲突核、Unicode 精确选区与模型作业账本。整页不发起付费模型调用，也不读写正式成果库。

## 为什么不是聊天套壳

| 能力 | 仅返回文本时需要另外处理的问题 | 拾构的本地程序 |
| --- | --- | --- |
| 并发修改 | 后写覆盖先写 | revision CAS；旧版本提交返回 409，并提供当前版本 |
| 局部修改 | 模型重写整段，可能顺手改别处 | 服务端按 Unicode 码点拼接；前缀、后缀、选区三段 SHA-256 复核 |
| 条件无解 | 让模型“再想想” | 有限枚举 + 位集过滤 + 冲突核 + 含候选证据的最小修正集合 |
| 偏好与验收 | 没有可复核边界 | 偏好只来自明确比较；机器检查与人工确认分别记录并绑定快照 |
| 模型调用 | 失败后静默重试 | 冻结模型/配置/输入指纹、调用上限与尝试记录；失败不伪装成功 |

这些不是界面文案：`/proof` 会直接读取当前服务的内存与隔离 SQLite，并允许你对沙盒提交真实请求。

## 四步做出自己的版本

1. **说想法**：用简单语言描述目标，按项目类型整理需求卡。
2. **找灵感**：结合本次回答与素材探索方向，查看示例、取舍和原文依据。
3. **留细节**：混搭章节、保留局部原文，修改先预览，再明确采用。
4. **成作品**：逐项关联需求与正文、标记缺口，导出正文和可追溯的交付包。

默认精简工作区突出下一步，顶部可展开完整工作台。选中文字可局部调整：模型只返回替换片段，服务端自己拼接；采用前不改动成稿，支持撤回。

想先感受“挑”的过程，可打开 http://127.0.0.1:8765/swipe（刷着拼）：一张卡一种写法，右滑留下、左滑划过、上滑继续；每拼完一段会看到整篇当前的样子，最后进入工作室继续修改和导出。留下会写入本地任务记录，划过不会记成偏好；示例内容均为演示数据。

当前可交付文本成果、方案与展示网页。`/web-studio` 支持封闭组件 Schema、属性级锁定、精确补丁、revision CAS 与离线 ZIP；代码执行和公网部署仍不在产品范围内。

## 本地运行

需要 Python 3.11+。基础功能使用标准库，无需安装第三方包：

```powershell
python -B server.py --port 8765
```

打开 http://127.0.0.1:8765/ ，或直接看 http://127.0.0.1:8765/proof 。Windows 也可双击 **启动拾构.cmd**。

只想快速试用、不想配置数据目录，可双击 **启动快速模式.cmd**，或运行：

```powershell
python -B server.py --quick
```

快速模式使用临时数据目录和随机端口，退出后数据保留但不会进入项目目录。

### 运行配置

命令行参数优先于环境变量：

| 参数 | 环境变量 | 默认值 |
| --- | --- | --- |
| `--host` | `TESSERA_HOST` | `127.0.0.1` |
| `--port` | `TESSERA_PORT` | `8765` |
| `--db` | `TESSERA_DB` | `data/workbench.sqlite3` |
| `--log-level` | `TESSERA_LOG_LEVEL` | `normal`（`quiet` / `normal` / `verbose`） |
| `--open` / `--no-open` | `TESSERA_OPEN` | 否 |

绑定非回环地址会关闭 Host 白名单校验并打印警告；服务本身没有鉴权，只应在受信任网络使用。

### 观测

`GET /api/metrics` 返回请求总数、状态码分布、异常类型、延迟分位数和活跃 AI 作业数。每个响应带 `X-Request-ID`，错误响应同时返回该编号，便于对照启动窗口日志。

### 容器

```powershell
docker compose up --build
```

默认映射到 `127.0.0.1:8765`，数据保存在 `tessera-data` 卷。镜像只包含基础工作台，不含可选研究依赖（NumPy/ONNX）；需要本地训练和语义查找时仍用本机研究环境。

AI 设置支持兼容 Chat Completions 的接口；填写自己的地址、模型和 Key。保存配置不发送生成请求。

默认业务数据在项目 `data/`，不会提交到版本库。Windows 凭证使用当前用户 DPAPI 加密。建议将项目、模型缓存和临时目录放在空间充足的磁盘；本项目开发环境使用 D 盘。

## 能力与算法

- 任务内明确偏好学习，保留线性对照与可选深度模型；深度模型没有在所有实验中胜过线性对照，不宣称全面更优。
- 有限候选组合的精确搜索、硬条件、偏好/改动量前沿、冲突核与最小调整集合。
- 章节×版本定制画布、篇幅×改动量地图。
- 单次预算的上下文灵感作业、冻结输入与供应商配置。
- 内容快照绑定的需求核对，按需复用冻结多语编码器查找语义线索。
- 版本检查、事务审计、修改草案、撤回与带证据的 ZIP。
- 展示网页的封闭组件 Schema、属性级锁定、精确补丁与离线导出。
- 网页内比较直接更新偏好推荐，提供属性贡献、推荐变化回看与实际训练记录。

可选研究环境见 `setup-research.ps1`；语义模型由 `scripts/setup_semantic_encoder.py` 单独准备，模型文件不包含在仓库中。部分浏览器验证脚本沿用开发机 D 盘依赖路径，其他环境需调整。

## 验证与边界

截至 2026-10-31，160 项 Python 检查通过，覆盖提交协议、快照链、约束求解、Unicode 拼接、作业生命周期、隔离沙盒与本页 HTTP 接口。四步流程、上下文灵感、需求核对、局部改写、保留与导出已用隔离模拟供应商验证；本地语义查找使用实际 ONNX 编码器。

模拟验证不能证明真实模型成品质量或用户时间收益。真实 API 验收仍记录过遗漏、误判、字数不足与违规新增章节，不能承诺任意任务直接交付。字面和语义定位都只提供核对线索；明确的机器规则与用户确认分别记录。/proof 的链路校验证明本地快照一致，不是密码学防篡改或分布式共识；约束求解是 3⁴ 的有限穷举，不是通用 SAT/ILP 求解器。

```powershell
python -B -m unittest discover -s tests -q
```
